1 Question and data provenance

The analysis asks whether a small reranker can select useful conversation memories for a new question under a fixed context-token budget. The unit of evaluation is a question. Candidate memories from one persona are correlated, so training, validation, and benchmark partitions must keep personas separate. Five-fold cross-validation also groups by persona; smoke runs with fewer personas use fewer folds and are development checks rather than full benchmark results.

The source training and validation files share personas, so their original split labels do not provide persona isolation. The ingestion stage preserves the benchmark, excludes its personas from development, and repartitions the pooled development personas deterministically into training and validation groups. The download manifest documents the exact repair; original_split, when present, retains source provenance. Counts below refer to these evaluation partitions.

The relevant-memory annotations are synthetic and incomplete. An annotated memory is a positive example; an unannotated candidate is not a verified negative. Retrieval recall and ranking metrics therefore measure recovery of these labels, not all useful context or the truthfulness of a final assistant answer. Exact alignment can fail, and the alignment report makes those failures visible.

2 Cleaning and partition checks

Required identifiers stay strings, including any leading zeroes. Cleaning trims identifier and metadata strings, preserves query and gold text exactly, standardizes boolean values, excludes unusable questions, history paths, or gold-message lists with reasons, and removes exact duplicate rows. It fails on persona leakage, conflicting duplicate questions, or role wrappers in queries. The gold annotation is used for alignment and evaluation, and never becomes a ranking feature.

4 Alignment and update annotations

The updated field is a dataset annotation. It does not establish a wall-clock timestamp or the age of a real user preference. The position feature measures relative order within a history; it is a recency proxy. A later message can be relevant to an update, but later order alone does not prove that an earlier fact was corrected. The no-position ablation checks how much the model depends on this proxy.

5 Feature distributions and training design

Conversation size is measured in memory turns after excluding complete-profile system messages. The aligned evidence position above and the distribution below use source order only. Token lengths of candidate turns appear in log_length.

The logistic model uses exactly BM25 score, semantic similarity, lexical overlap, log memory length, and relative history position. The no-position model removes the last feature. A 300-tree probability forest uses the same five features with seed 310, mtry = 2, min.node.size = 10, and two threads. RRF is a retrieval baseline and is excluded from the learned model inputs.

Logistic features are centered and scaled using training rows only. Each cross-validation fold estimates its own centers and scales from the remaining personas. A constant or linearly redundant feature receives a zero coefficient and is recorded in training_report.json. Validation predictions come from models fitted to the complete training partition. Benchmark features are scored later using frozen models; the training program does not read benchmark files.

6 Retrieval outcomes

Only verified computed rows from reports/cv_query_metrics.csv, reports/val_query_metrics.csv and reports/benchmark_query_metrics.csv appear below. Compare methods on the same query set and token budget. Candidate recall limits the best possible reranking result. Report candidate-pool coverage alongside ranking quality, and interpret results for updated questions separately when enough examples exist. Grouped out-of-fold predictions support development comparisons without scoring a persona using a model trained on its own candidates.

if (!is.null(metrics) && nrow(metrics)) {
  show_table(head(metrics, 20), caption = "First computed per-query metric rows")
  numeric_names <- setdiff(names(metrics), c("query_id", "persona_id", "split", "method", "updated", "topic_query"))
  numeric_names <- numeric_names[vapply(metrics[numeric_names], function(x)
    all(is.finite(suppressWarnings(as.numeric(x)))), logical(1))]
  if ("method" %in% names(metrics) && length(numeric_names)) {
    values <- metrics
    values[numeric_names] <- lapply(values[numeric_names], as.numeric)
    groups <- intersect(c("split", "method"), names(values))
    summary <- aggregate(values[numeric_names], values[groups], mean)
    show_table(summary, digits = 4, caption = "Unweighted means over reported queries")
  }
  summaries <- lapply(c("cv", "val", "benchmark"), function(s) {
    table <- read_optional(paste0("reports/", s, "_summary.csv"))
    if (!is.null(table)) table$split <- s
    table
  })
  summaries <- Filter(Negate(is.null), summaries)
  if (length(summaries)) {
    intervals <- do.call(rbind, summaries)
    intervals <- intervals[intervals$metric == "budget_recall", , drop = FALSE]
    for (name in c("mean", "ci_low", "ci_high")) intervals[[name]] <- pmr_finite_number(intervals[[name]], name)
    print(ggplot(intervals, aes(method, mean)) +
      geom_errorbar(aes(ymin = ci_low, ymax = ci_high), width = 0.18, color = "#207D83") +
      geom_point(color = "#207D83", size = 2) + coord_flip() + facet_wrap(~ split) +
      scale_y_continuous(limits = c(0, 1)) +
      labs(x = NULL, y = "Annotated evidence recall at 2,000 tokens",

  }
} else {

7 Reproducibility and limits

Run Rscript R/bootstrap.R first, then the documented download, cleaning, alignment, feature, training, and evaluation commands. Rscript R/render.R --output reports/eda.html renders this notebook from the current artifacts. Keep development samples and final benchmark results identified in their manifests. Hyperparameters and token budgets should be selected using training/validation evidence before one final benchmark evaluation.

This is an annotated-memory retrieval study. It does not establish causal effects, personalization quality for real users, or performance on arbitrary conversations. Synthetic prompts, incomplete labels, exact-alignment exclusions, and query correlations within personas limit interpretation. Bootstrap intervals should resample personas when reporting uncertainty over this clustered dataset.
