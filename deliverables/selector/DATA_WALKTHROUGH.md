# 從原始對話到人格範例：白話處理步驟

這個專案替 Apersona 做的是「挑範例的模組」。既有 persona prompt 決定角色是誰；本模組根據當下問題，找出有助於呈現這個角色的行為範例。它不把資料集中陌生人的故事變成角色自己的往事。

## 1. 下載有現成標籤的原始資料

資料來自官方 [BIG5-CHAT](https://huggingface.co/datasets/wenkai-li/big5_chat)，固定 revision `adf1cd37997b498ff7b220827eaacdeb8aa6d905`。資料卡標示 Apache-2.0。

下載得到 100,000 筆 CSV 記錄；程式核對檔案 SHA-256，避免未來資料更新後卻還沿用舊實驗名稱。原始 CSV 保留不修改，整理後另存。

每筆資料的標籤是「生成時要求表現的特質」，例如 `openness_low`。它不是對真人測驗後得到的診斷，也不能說另外四種特質不存在。

## 2. 先分清楚誰在說話

真實訓練記錄 `big5-000005` 的提問者建議週末帶孩子出遊；目標回答者則擔心孩子太興奮、弄亂環境或下雨，傾向維持原來的安排。指定標籤為 `openness_low`。

原始欄位分成：

| 欄位 | 用途 |
|---|---|
| `train_input` | 對方提出的問題／情境 |
| `train_output` | 本次要分類的目標回答 |
| `trait`、`level` | 訓練與評估時使用的既有標籤 |
| `train_instruction` | 包含指定人格的生成指令，禁止放進特徵 |
| `original_index`、`head` | 找出相關情境，避免切分洩漏 |
| `personx`、`persony` | 保留說話者對應，並做名字遮蔽 |

這筆回答也提到擔憂，可能和神經質傾向的表現重疊。這正是要保留原文並分析分類混淆的原因；不能把生成標籤當成毫無歧義的心理真相。

## 3. 缺少必要內容就排除，不補寫

294 筆缺少輸入、65 筆缺少回答，兩者有重疊；最後共排除 **344 筆**，保留 **99,656 筆**。每一筆排除都有原因與來源記錄。

不叫 LLM 編造缺少的回答，因為這樣會把新的生成偏差混進原資料，也無法再對回來源。

## 4. 保留原文，另外做模型版本

統一多餘空白與換行，保留否定詞、標點和原文字意。原始名字 Dorothy、Benzion 在模型輸入中分別改為 `PERSON_Y`、`PERSON_X`。原文仍完整保存，引用時可以查回。

因此「模型看到的文字」與「供人檢查的原文」是兩個明確欄位，沒有偷偷把 AI 改寫的摘要當成證據。

## 5. 把互相關聯的情境綁在一起

同一個原始情境有十種特質高低版本。如果直接逐筆抽籤切資料，模型可能在訓練時看過同題的另一個版本。

所以先把相同 `original_index`、重複情境描述、名字遮蔽後相同的提問連起來。A 和 B 相同、B 又和 C 相同時，A、B、C 一起移動。缺值資料也先參與這個連結步驟，避免刪掉一筆後把原本相連的群錯拆。

最大群組有 270 筆；程式不為了湊比例而拆開它。這裡的「情境群組」用來隔離資料；後面 graph 的 30 個 k-means 情境類群是另一個用途，不能混為一談。

## 6. 整群切成訓練、驗證、測試

| 分組 | 保留筆數 | 能做什麼 |
|---|---:|---|
| 訓練 | 69,783 | 學分類模型、詞彙表、標準化及 k-means |
| 驗證 | 15,296 | 選分類器與檢索權重，不拿來宣稱最終效果 |
| 測試 | 14,577 | 方法凍結後才評估分類與回答 |

驗證和測試各自再分成範例庫與提問集。測試範例庫有 7,226 筆，提問集有 7,351 筆；同一群組不會同時出現在兩邊。

## 7. 把文字轉成數字，再由 R 學分類

TF-IDF 表示哪些詞在訓練資料中特別有區別性。固定 MiniLM 編碼則把文字轉成 384 個數字，用來表示語意。長回答分窗處理，不直接丟掉尾巴。

R 比較 multinomial logistic regression 與 random forest，並比較「只看回答」和「情境加回答」。交叉驗證也按群組切；每一折的詞彙表及前處理只用該折的訓練部分估計。

分類器輸出十種標籤的分數。這些分數表示和資料生成標籤的相似程度，不是某個人有某種人格的機率。Macro-F1 對十類平均，混淆矩陣幫助我們找出哪些特質容易混在一起。

「資料已經有標籤，為什麼還要學分類？」因為公開資料的標籤用來教模型；日後 Apersona 收到的新記憶通常沒有這些人工標籤。分類器的用途是替新文字估計分數，讓後面的範例選取能運作。

## 8. 收到新問題時，分類與 graph 才派上用場

例如目標角色重承諾，問題是臨時提前交件。系統先從已被 Apersona 允許使用的範例中，找語意最接近的 50 筆。

B 只按情境相似度排；C 同時考慮目標特質的分類分數；D 使用同一批候選，加上情境類群與特質節點做 PageRank。三者最多挑五筆，使用相同的記憶容量上限。

實作採保守的 2,000 UTF-8 bytes 上限，以確保不超過 2,000 tokens；會另外記錄本機模型實際計算的 prompt token 數。這不是宣稱把 2,000 tokens 用滿。

## 9. 放進 persona prompt，但不能偷換成自傳

記憶包保留範例 ID、原文、來源、分類分數、排序分數及記憶類型。

`behavioral_exemplar` 是「參考別人如何反應」；`owned_episode` 才是「這個角色自身的事件」。後者必須有符合角色的 owner ID。權限、時間及記憶狀態仍由 Apersona 原系統判斷。

因此對 Apersona 的貢獻是可替換、可測試的分類與挑選模組，不需要重建整個記憶引擎，也不需要把 Big Five 換成產品唯一的人格定義。

這個版本一次測一個 Big Five 高低目標。責任、界線、紅線或多種特質組合都不能只換名稱就宣稱已驗證；可以復用流程，但需要相應標籤、重新訓練與應用評估。

## 10. 分開驗證兩種成果

第一種成果是分類效果：能否辨識未見情境下的生成標籤。第二種成果是應用效果：AI 的立場與語氣是否更符合目標角色、是否仍然切題、有沒有捏造經歷。

第二種成果必須由兩位同學評同一批 100 組匿名回答。A 是只有 persona prompt；B、C、D 分別加入三種選取方法。C 對 B 檢查分類的價值，D 對 C 檢查 graph 的額外價值。

在人工評分完成前，可以交付資料、模型、接口和 Demo，但不能宣稱人格一致性已改善。若 graph 沒有顯示額外幫助，保留較簡單的 C 也是有用的研究結果。
